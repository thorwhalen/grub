grub.backends

Search backends: the engines that score documents against a query.

Every backend implements the same tiny interface:

  • index(docs) – build an index over a list of text documents.

  • scores(query) – return a relevance score per document.

  • query(query, n) – return the top-n (indices, scores).

Three backends ship with grub:

  • TfidfBackend – lexical TF-IDF + cosine similarity (default, no extra dependencies).

  • SemanticBackend – dense embeddings; understands meaning, not just words. Needs sentence-transformers (pip install grub[semantic]) or any embedding function you supply.

  • HybridBackend – a weighted blend of the two.

Pick a backend by name with make_backend().

class grub.backends.HybridBackend(*, alpha: float = 0.5, tokenizer=<function camelcase_and_underscore_tokenizer>, embed=None, model: str = 'all-MiniLM-L6-v2')[source]

A weighted blend of lexical (TF-IDF) and semantic search.

alpha is the lexical weight: 1.0 is pure TF-IDF, 0.0 is pure semantic, 0.5 (default) gives an even mix.

class grub.backends.SemanticBackend(*, embed=None, model: str = 'all-MiniLM-L6-v2')[source]

Dense-embedding search: matches meaning, not just shared words.

Supply your own embed callable (list[str] -> 2D array) to use any provider, or leave it None to lazily load a local sentence-transformers model.

Embed texts into an L2-normalised matrix.

class grub.backends.TfidfBackend(*, tokenizer=<function camelcase_and_underscore_tokenizer>, **tfidf_kwargs)[source]

Lexical search via TF-IDF vectors and cosine similarity.

Fast, dependency-light, and excellent when the query shares actual words with the documents – the right default for code and docs.
